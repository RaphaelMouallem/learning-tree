# Using a learning tree in Obsidian

Obsidian reads plain files, so a tree folder dropped into a vault already works: no plugin and no special API. The agent only needs file access to the vault folder (a local agent such as a coding agent running in the vault; a hosted chat sandbox cannot see your vault, so use the zip there).

## Layout

```
<vault>/Learning/<tree_id>/
├── tree.json
├── overview.md         generated; pin it as the tree's home note
└── nodes/<slug>.md
```

Ask for the vault path the first time, then reuse it. Never write inside `.obsidian/`.

## How the files map to Obsidian features

| File content | Obsidian feature |
|---|---|
| Frontmatter (`id`, `tree`, `type`, `gear`, `est_hours`, `tags`) | Properties; filter or query by them |
| `tags: [learning-tree/<tree_id>]` | Nested tag, groups all nodes of a tree |
| `- [ ]` todos | Native checkboxes; ticking one in Obsidian is exactly how progress is recorded |
| Standard Markdown links `[Title](nodes/x.md)` | Work in Obsidian and everywhere else; chosen over wikilinks for portability |
| Mermaid block in `overview.md` | Renders as the tree map |
| "Position in tree" block at the bottom of each node file (generated by `export.py`) | Real links for Part of / Requires / Unlocks, so the **graph view** shows the structure instead of loose files |
| `tree.canvas` (from `export.py --canvas`) | A Canvas with one group per gear, columns by prerequisite depth, status colors and arrows |

## Workflow

1. Learner ticks boxes in Obsidian as they work.
2. Agent runs `progress.py` to read progress and `export.py --no-zip` to refresh `overview.md`.
3. The overview note shows percentages, status per gear and the Mermaid map.

`tree.json` is not meant to be edited in Obsidian; the agent edits it.

## Optional extras

- If the agent has an Obsidian syntax skill available (for example the community `obsidian-skills` collection, which covers Obsidian-flavored Markdown, Bases and JSON Canvas), consult it for formatting details before adding features such as callouts or a Bases dashboard.
- Canvas cards are plain text by default. Pass `--vault-prefix <path of the tree folder inside the vault>` (for example `Learning/rust`) and each card gets an `[[open]]` wikilink to its note. The canvas is a snapshot: re-run `export.py --canvas` to refresh colors and counts.

## Pitfalls

- Do not rename node files by hand; the `file` path in `tree.json` must match. If you do, update `tree.json` and re-run `validate_tree.py`.
- `overview.md` is overwritten on every export. Put personal notes in separate notes, linked from it.
- Each node file ends with a generated block between `learning-tree:links:start` and `learning-tree:links:end` comments. Everything between those markers is rewritten on export; write your own notes above it.
